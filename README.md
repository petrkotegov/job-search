# job-search

В проекте разделены поиск работы и разработка инструментов для него.

## Материалы поиска работы

Всё, что непосредственно связано с поиском работы, хранится в `private/`: планы поиска, предварительные диалоги, версии резюме, найденные вакансии, отклики, переписка и учёт того, кому какое резюме отправлено.

Папка `private/` исключена из Git через `.gitignore`.

## Инструменты

Вне `private/` размещаются код инструментов для поиска работы, их документация, конфигурация и планы разработки.

## Задачи

В GitHub Issues ведутся только задачи разработки инструментов: новые возможности, исправления и улучшения. Задачи самого поиска работы, вакансии и статусы откликов учитываются внутри `private/`.

## Парсер сохранённых страниц HH

Нужен Node.js 22 или новее. Установка зависимостей: `npm ci`.

Сохраните страницы поиска или полные вакансии через SingleFile в обычном формате HTML. В параметрах
автосохранения задайте задержку, достаточную для появления всех карточек.
Исходники положите в отдельный каталог внутри `private/`.

```sh
npm run parse:hh -- private/hh/search/raw private/hh/search/vacancies.json
npm run parse:hh -- private/hh/details/raw private/hh/details/vacancies.json
npm test
```

Первый аргумент — каталог с HTML-файлами или один файл; второй — путь к JSON.
Тип страницы определяется автоматически. Выдачу и полные описания удобнее хранить
и разбирать отдельными наборами: при одинаковом ID сохраняется первое вхождение.
Повторный запуск обновляет итоговый JSON. Парсер работает локально, не обращается
к HH и не исполняет код сохранённых страниц.

Для выдачи сохраняются ID, ссылки, названия, работодатели, зарплаты с условиями,
опыт, местоположение, видимые станции метро, отметки условий работы и текст карточек.
Отсутствующие поля остаются `null` или пустым списком: отсутствие отметки
«Можно удалённо» не означает обязательную работу в офисе. Текст зарплаты сохраняется
без попытки угадать валюту, налоги или период выплат.

Вакансии объединяются по ID; для каждого вхождения остаются файл и позиция карточки.
При расхождении дублей сохраняются поля первого вхождения и предупреждение.
Для каждой страницы записываются URL и время из комментария SingleFile, номер
страницы, размер выдачи, счётчик HH и число найденных карточек. Если число карточек
не совпадает с ожидаемым, парсер выдаёт предупреждение. Страница без карточек или
карточка без названия/корректной ссылки останавливает разбор без записи результата.

Для полной вакансии дополнительно сохраняются `description` (текст с абзацами
и пунктами), `skills` (метки ключевых навыков), `employment`, `hiring_format`,
`schedule`, `working_hours`, `work_format`, `address`, `published_at` и `valid_through`.
Условия остаются в формулировках HH: «удалённо или гибрид» не превращается в полную
удалёнку. «Уровень дохода не указан» записывается как `salary: null`.
Даты и город `location` берутся из сохранённого JSON-LD; остальные поля — из видимых
блоков HTML. `valid_through` — техническая дата из копии, а не проверка доступности
вакансии сейчас. Рекомендации других вакансий, меню, скрипты и рекламное оформление
не попадают в описание. Список `skills` содержит только явные метки HH, а остальные
упомянутые технологии остаются в тексте описания.

Структура результата общая: `sources`, `summary`, `warnings`, `vacancies`.
У полных страниц в `sources` указано `page_type: "vacancy"`; `summary.card_count`
считает записи до объединения, в том числе по одной на полную страницу.
Полная вакансия без ID, названия или описания останавливает разбор до записи JSON.
Отсутствующие необязательные данные остаются `null` или пустыми списками.

Парсер сохраняет все вакансии без отбора по названию или критериям поиска.
Содержимое, которое браузер не загрузил или SingleFile удалил, восстановить нельзя.
При изменении разметки HH могут потребоваться новые селекторы.
Тесты используют вымышленные карточки и полные страницы; личные исходники и результаты остаются в `private/`.

## Последовательная загрузка HTML HH

На машине, с которой доступен `hh.kz`, можно использовать Python 3 и curl:

```sh
python3 scripts/download-hh.py --input private/hh/missing.json --output private/hh/downloaded
python3 -m unittest discover -s tests -p 'download_hh_test.py'
```

Входной JSON — массив объектов с числовым строковым `id`. Скрипт загружает
`https://hh.kz/vacancy/<id>` по одному, с паузой 6,5 секунды между запросами.
Пауза меняется через `--delay`; повторных попыток нет. Ответы 403/429,
капча, отсутствие описания, неверный ID и ошибки соединения останавливают
весь запуск. Ответы 404/410 учитываются как недоступные вакансии.
Исключение для 403 — известная страница «Вам недоступна эта вакансия» с требованием
войти пользователем с правом просмотра: такая вакансия отмечается `restricted`,
загрузчик не пытается получить к ней доступ и переходит к следующей.

В `raw/` остаются исходные HTML и заголовки ответов, в `state.json` — прогресс,
статусы и контрольные суммы успешных файлов. Наличие `started.json` защищает
от случайного повторного запуска в ту же папку. HTML сохраняется без загрузки
картинок, стилей и скриптов; это обычный ответ сервера, а не архив SingleFile.
Парсер поддерживает полные страницы `hh.ru`, `hh.kz` и `hh.uz`, включая
региональные поддомены. Без SingleFile URL берётся из canonical, время
сохранения остаётся в журнале загрузчика.
